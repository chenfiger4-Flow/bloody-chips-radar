# 带血筹码雷达 · Bloody Chips Radar

> 一套基于量价与威科夫（Wyckoff）方法的**恐慌—确认—买点**状态机。
> 它不预测涨跌，只回答一个问题：**这只标的现在是不是在"带血筹码"阶段，以及市场有没有用成交量确认。**

网页面板：https://chenfiger4-flow.github.io/bloody-chips-radar/
推送渠道：Telegram（每次运行后自动发送）

---

## 这套系统是什么、不是什么

**是：**
- 一个纪律执行器。把"恐慌时只研究、确认后才试探、信号矛盾就空仓、失效无条件止损"写成代码，替代情绪判断。
- 一个观察池扫描器。每天收盘后扫一遍 13 个标的，给出每个标的所处的威科夫阶段。
- 一个数据留痕工具。每条数据都标注时间、来源和缺失项，不编数字。

**不是：**
- 不是选股器。观察池是手工维护的，系统不会自己找新标的。
- 不是抄底工具。恐慌回撤本身**永远不会**触发买入信号。
- 不是仓位管理器。系统不回答"现金什么时候投出去"，只在 S4 给出标的级的买点；仓位由固定风险预算（单笔 0.5%）反推，不按现金比例分配。

## 核心逻辑：状态机

系统对每个标的独立维护一个状态。状态转换的**唯一核心证据是成交量**，价格形态只是辅助。

| 状态 | 威科夫术语 | 含义 | 允许的动作 |
|---|---|---|---|
| **S0** | — | 无信号，正常波动 | 不动 |
| **S1** | 恐慌回撤 | 60 日回撤超阈值，进入研究名单 | **只研究，不买** |
| **S2** | SC（抛售高潮） | 放量长下影 / 收盘远离低点，恐慌集中释放 | 记录 SC 低点，等待测试 |
| **S3** | ST（二次测试）/ LPS（最后支撑点） | 缩量回踩 SC 低点附近且未破 | 准备，仍不买 |
| **S4** | SOS（强势信号） | 放量突破测试区间高点，供需反转确认 | **允许试探仓** |
| **S5** | 失效 | 该标的的基本面失效条件被命中 | 剔出候选，直到条件解除 |
| **S9** | 止损 | 持仓后跌破 SC 低点或结构破坏 | **无条件止损，不讨论** |

几条硬规则：
1. 任何状态下，信号相互矛盾（例如价格形态像 ST 但成交量放大）→ 输出"信号混乱，空仓观望"。
2. S1 → S4 必须依次经过 S2、S3，不允许跳级。
3. 失效条件（S5）优先级高于一切量价信号：基本面坏了，再漂亮的 K 线也不看。
4. 所有阈值写在 `config.yaml`，**均未经回测**，属于经验参数。

## 观察池

| 类别 | 标的 | 数据源（优先级） | 频率 |
|---|---|---|---|
| 指数 ETF | SPY、QQQ | yfinance | 每交易日收盘后 |
| 大盘科技 | AAPL、MSFT、NVDA、AMZN、GOOGL、META、TSLA | yfinance | 每交易日收盘后 |
| 次新股 | SPCX（SpaceX）、CRCL | yfinance | 每交易日收盘后 |
| 加密 | BTC | yfinance | 每 12 小时 |
| 加密 | HYPE | Hyperliquid 原生 API → yfinance → CoinGecko | 每 12 小时 |

每个标的都配有**可量化的失效条件**（写明口径和数据来源），在 `config.yaml` 的 `failure_conditions` 段。例如 AMZN 的三条：AWS 增速 < 20%；AWS 经营利润率 < 32%；经营现金流 TTM 同比下滑。

### 宏观面板

每次运行附带五个宏观指标及联读结论：VIX、加密恐贪指数、美债 10Y 收益率、美元指数 DXY、半导体 ETF SMH。系统会按预设规则给出"压力分"四档结论，但宏观只用于**校准解读语气**，不直接改变任何标的的状态。

## 输出

**Telegram 消息**（每次运行）
1. 宏观面板 + 联读
2. 各标的状态表 + 一句话解读
3. 状态发生变化的标的（重点提示）
4. 加密标的资金费率解读（年化分五档，与价格方向交叉）
5. 数据源与缺失项声明

**网页面板**（GitHub Pages）
同样内容的表格版，多一列"解读"，方便回看。

## 部署

### 1. Fork 或 clone 本仓库

仓库需设为 Public，GitHub Pages 才能免费使用。

### 2. 配置 Secrets

进入 **Settings → Secrets and variables → Actions**，添加：

| 名称 | 内容 |
|---|---|
| `TG_BOT_TOKEN` | Telegram Bot Token（从 @BotFather 获取） |
| `TG_CHAT_ID` | 接收消息的 chat id |

注意：粘贴 token 时**不要带末尾换行**，否则 Telegram API 会静默拒绝。代码里已做 `.strip()` 兜底，但仍建议存干净。

### 3. 开启 GitHub Pages

**Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`，目录 `/docs`。

### 4. 手动触发一次

**Actions → 带血筹码雷达 → Run workflow**，等待运行完成后检查：
- 日志里有 `[TG] status=200`
- 日志里有 `[HL] HYPE 取得 xxx 根日线`
- Telegram 收到消息
- 网页面板更新

### 定时规则

默认 `cron` 在 `.github/workflows/radar.yml` 中。由于加密标的会丢弃 UTC 当日未收盘的 K 线，一天内多次运行看到的是同一根 K，建议每天一次即可（UTC 00:15，即北京时间 08:15）。

## 已知限制

- **阈值未回测。** 所有 S1–S4 判定参数都是经验值，系统只保证"按规则执行"，不保证"规则正确"。
- **加密 K 线口径。** 加密 7×24 交易，脚本统一丢弃 UTC 当日未收盘 K，因此看到的永远是"昨天"的完整 K。
- **CoinGecko 备用源无真实高低价。** HYPE 若回退到 CoinGecko，上影线和收盘位置为估算，S2 判定可信度打折；网页上数据源列会标明。
- **次新股窗口不足。** SPCX、CRCL 上市时间短，60 日指标用 `min_periods=20` 计算，早期数值噪音大。
- **失效条件是人工维护的。** 财报数据不会自动更新，需要在每季财报后手工核对 `config.yaml`。
- **yfinance 是非官方接口。** 可能因 Yahoo 改版而临时失效，届时日志会报错并标注缺失项。

## 使用纪律（给自己看的）

1. 收到 S1 不是买入理由，是打开研报的理由。
2. 收到 S4 才允许开试探仓，且单笔风险不超过总资金 0.5%。
3. 看到"信号混乱"，什么都不做。
4. 触发 S9，先卖再想。
5. 每次运行都看数据源和缺失项，数据不全时不据此做任何决策。
